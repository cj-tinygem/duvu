# DUVU 프로젝트 계약과 문서 스모크 검증 2026-05-05

## 요약

DUVU는 프로젝트별 디자인 계약을 생성하고 검증하는 `duvu project init|audit` 흐름을 포함한다. 이 흐름은 `DUVU.md`를 사람이 읽는 정본으로 두고, `.duvu/project.json`, `.duvu/contract.json`, `.duvu/tokens.dtcg.json`을 기계가 재사용하는 구조화 계약으로 둔다.

이번 상태에서는 문서와 패키징 회귀를 막기 위해 `bin/docs-smoke.js`가 추가되었다. 이 스모크는 현재 존재하는 `CALIBRATION.md`를 부재로 설명하는 stale Cortex 문구, 핵심 Markdown 로컬 링크 파손, `data/references/platforms.md`의 토큰 밖 CSS 직접값 재발을 검사한다.

## 구현 표면

- `bin/duvu.js`: `project init`과 `project audit` 명령 표면, 프로젝트 manifest, DUVU.md 생성, DTCG 토큰 계약 생성/검증 흐름.
- `README.md`, `docs/PRD.md`, `docs/GAPS.md`, `skills/SKILL.md`: 프로젝트별 DUVU 계약과 선택적 Picasso 연계의 제품/운영 설명.
- `data/references/platforms.md`: CSS 예시에서 hover lift, active duration, touch target, active scale 등을 토큰으로 표현.
- `bin/docs-smoke.js`: 문서 링크와 stale 설명, 플랫폼 레퍼런스 직접값 회귀 검증.
- `package.json`, `bin/package-smoke.js`: docs smoke를 `npm test`와 패키지 smoke에 연결.

## 검증 상태

2026-05-05 기준 다음 검증이 통과했다.

- `npm test`
- `npm audit --audit-level=moderate`
- `git diff --check`
- `node --check bin/docs-smoke.js && node --check bin/package-smoke.js`
- dark visual audit 174개 화면/페이지
- light visual audit 174개 화면/페이지

## 운영 판단

이 변경은 새 외부 의존성을 도입하지 않는다. 문서 스모크는 기존 테스트 체계에 작은 회귀 게이트를 추가하는 수준이라 과도한 엔지니어링으로 보지 않는다. Picasso 연계는 필수가 아니라 선택적 독립 도구 연계로 문서화되어, DUVU 단독 사용 경계를 유지한다.
